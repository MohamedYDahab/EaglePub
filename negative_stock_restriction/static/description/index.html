How It Works

One check, four outcomes, wired into the three places stock actually leaves the building.

🛒 Action Pay · Confirm · Deliver → 🔍 Check Quantity vs demand → 🚫 Block or Warn Per configured mode → 🔑 Override PIN or bypass group

Where It Checks

Area Trigger Point Hard Block Soft Warning
Stock Transfers _action_done() on outgoing moves UserError raised Warning logged
Point of Sale Pay button + Validate button Error popup, or PIN override Confirm popup
Sale Orders action_confirm() UserError raised Warning + chatter note

Exception Priority

Exceptions are evaluated in this order. If any match, the product is skipped:

No stock issues? If every product has sufficient quantity, nothing happens — no popups, no interruption, just the standard Odoo flow.

Enforcement in the Point of Sale

When the cashier hits Pay or Validate, every order line is checked before the order goes through.

🛑 Hard Block Mode The action is stopped. The cashier sees exactly which products are short and by how much, and cannot proceed without a manager. ⚠️ Soft Warning Mode A confirmation popup appears instead. The cashier can proceed or cancel, and the decision is recorded.

Soft warning — the cashier decides

Manager PIN Override

With override enabled, a hard-blocked order shows a PIN prompt instead of a dead end. A user in the override group authorises the sale on the spot.

Manual Stock Check Button

A dedicated Stock Check button sits on the POS product screen. Press it any time to see stock levels for everything in the current order — before the customer reaches the till.

Stock Transfers & Sale Orders

The same rule, applied in the back office.

Delivery Orders

Validating a delivery order checks whether the move would push stock negative. Only outgoing moves are checked — internal transfers, receipts, and returns pass through untouched.

Sale Order Confirmation

Confirming a Sale Order checks every line against that order's warehouse. In soft mode the warning is posted to the order chatter, so there is a permanent record of who confirmed against low stock.

Which Quantity Gets Checked

Pick the definition of "in stock" that matches how you actually trade.

Type Formula Best For
On Hand Physical stock in the location Simple retail where reservations don't matter
Available DEFAULT On Hand − Reserved Most businesses — respects pending orders
Forecast Available + Incoming − Outgoing Selling against expected receipts
One setting, everywhere. The chosen quantity type drives POS badges, POS blocking, transfer blocking, and SO confirmation alike.

Frequently Asked Questions

Do cashiers need to restart the POS session to see updated stock? No. Badges refresh after every completed sale, when the tab regains focus, and on a configurable interval. The session stays open.
Can a cashier get around the hard block? Only through the Bypass group, or when Manager Override is enabled and someone in the override group enters the correct PIN. A regular cashier cannot proceed.
What happens if the network drops during a stock check? The module fails open. If the RPC call errors or times out, the sale proceeds — connectivity problems never leave the POS unusable.
Does it handle multi-warehouse or multi-location setups? Yes. Each POS resolves its source location from its operation type, so every till checks the stock that actually applies to it.
Are consumables and services affected? No. Only storable products are checked. Consumables and services are treated as unlimited and are never blocked.
What about lot- and serial-tracked products? Stock transfers check lot-specific availability when lots are assigned to the move. POS and Sale Orders use overall product availability at the location.
